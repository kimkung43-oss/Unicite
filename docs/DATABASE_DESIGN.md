# Database Design Document

## Unicite Integrated Learning System

**Version:** 1.0
**Date:** November 2026
**DBMS:** PostgreSQL 12+
**ORM:** Hibernate 6.2.5 (via Spring Data JPA)

---

## 1. Overview

The Unicite ILS database stores all persistent data for the learning system. The schema is auto-generated by Hibernate from JPA entity annotations (`spring.jpa.hibernate.ddl-auto=create`). This document describes all 24 entities, their fields, relationships, and recommended improvements.

## 4. Normalization Analysis

The schema follows third normal form (3NF) as described in the thesis:

### First Normal Form (1NF)
All columns contain atomic values. Multi-valued relationships (e.g., user-role, user-course) are represented via join tables or separate entities.

### Second Normal Form (2NF)
All non-key attributes depend on the full primary key. Since all tables use single-column surrogate keys (IDENTITY), 2NF is satisfied by default.

### Third Normal Form (3NF)
No transitive dependencies exist between non-key attributes. Each attribute depends directly on the primary key. The thesis notes that `venueName` in `courses` could theoretically be extracted to a separate `CourseDetails` table, but this level of normalization adds complexity without practical benefit for this domain.

### Denormalization considerations
- The `users_courses` join table (from `Users.courses` without `mappedBy`) duplicates the relationship already modeled by `courses.fk_user_id`. This should be resolved by adding `mappedBy = "user"` to the `@OneToMany`.

## 5. Known Schema Issues

| Issue | Table(s) | Description | Recommendation |
|-------|----------|-------------|----------------|
| Duplicate join table | users_courses | `Users.courses` creates a join table, but `Courses.user` already has `fk_user_id` | Add `@OneToMany(mappedBy = "user")` on `Users.courses` |
| Misnamed FK | announcements.fk_user | Points to `Courses`, not `Users` | Rename to `fk_course` |
| Misnamed FK | grades.fk_course | Points to `CourseGroups`, not `Courses` | Rename to `fk_course_group` or change target entity |
| Inconsistent ID generation | roles | Uses `GenerationType.AUTO` (sequence) while all others use `IDENTITY` | Change to `IDENTITY` for consistency |
| snake_case Java fields | conversation_id, message_id, thread_id, task_id, note_id, announcement_id, course_group_id | Violates Java naming conventions | Rename to camelCase, use `@Column(name = "...")` |
| Missing indexes | fk columns | No explicit indexes on foreign keys | Add `@Index` annotations for query performance |
| Cascade issues | course_group_members, course_groups | `CascadeType.ALL` on `@ManyToOne` can cause unintended deletions | Change to `CascadeType.PERSIST` or remove cascade |
| EAGER fetch | users.courses | Loads all courses for every user query | Change to `FetchType.LAZY` |
| EAGER fetch | forum_threads.forumReplies | Loads all replies for every thread query | Change to `FetchType.LAZY` |

## 7. Migration Strategy

### Current state
- `spring.jpa.hibernate.ddl-auto = create` drops and recreates all tables on every restart
- No migration history or version control for schema changes

### Recommended migration path

**Step 1:** Switch `ddl-auto` to `validate` and capture the current auto-generated schema as the baseline migration.

**Step 2:** Adopt Flyway for versioned migrations:
```
src/main/resources/db/migration/
├── V1__baseline_schema.sql        # Captured from current ddl-auto=create output
├── V2__fix_naming_issues.sql      # Rename misnamed FK columns
├── V3__add_indexes.sql            # Add indexes on all FK columns
├── V4__add_notification_tables.sql
├── V5__add_quiz_tables.sql
└── V6__add_gamification_tables.sql
```

**Step 3:** Add Flyway dependency to `pom.xml`:
```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
```

**Step 4:** Configure in `application.properties`:
```properties
spring.jpa.hibernate.ddl-auto=validate
spring.flyway.enabled=true
spring.flyway.locations=classpath:db/migration
```
